# תהליך עבודה — סבבי שיפור ושדרוג

המסמך הזה מגדיר איך מתבצע כל סבב שיפור באתר, ומחזיק את ה-backlog המתועדף.
הוא נכתב כדי שכל סוכן או מפתח שממשיך את העבודה יתחיל מאותה נקודה, ולא ינחש.
מקור אמת לכללי העבודה: `CLAUDE.md`. זיכרון מתמשך: טבלת `agent_memory` בפרויקט orzadik.

## המחזור — כל סבב

1. **מדידה.** נתונים חיים מפרויקט Supabase `whtjslgrrfzehivrknuv` בלבד:
   הזמנות ומשפך, עגלות, בריאות הקטלוג (תמונה, מחיר, קטגוריה, תיאור),
   קטגוריות גדולות בלי מדריך, advisors של אבטחה וביצועים, מצב CI והפריסה האחרונה.
2. **בחירה.** פריט אחד או שניים מה-backlog למטה — לפי השפעה מדידה, לא לפי נוחות.
   מה שדורש החלטת בעלים (כסף, משפט, הגדרות בדשבורד) לא מבוצע — נרשם ב"ממתין לבעלים".
3. **בנייה.** שינוי מינימלי וממוקד.
   - לוגיקה: מודול טהור עם בדיקות Vitest.
   - תוכן: מבוסס על נתוני הקטלוג החיים; בלי מחירים בטקסט; מקורות הלכתיים מצוטטים כלשונם;
     היכן שהמנהג משתנה — מתארים ומפנים לרב.
   - מיגרציה: קובץ ב-`supabase/migrations` + החלה על `whtjslgrrfzehivrknuv`, ובדיקה שהשורה
     השמורה זהה לקובץ (md5).
4. **אימות.** `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`,
   ובדיקה חזותית בתצוגה מקומית (mock) בגודל מובייל.
5. **שילוב.** PR → CI ירוק → מיזוג → בדיקה ש-`deploy.yml` הסתיים בהצלחה.
   האתר החי מתעדכן רק מהפריסה ל-Cloudflare; preview של Vercel אינו האתר.
6. **תיעוד.** upsert ל-`agent_memory` (לפי `key`) ועדכון ה-backlog כאן.
7. **דיווח.** מה נעשה, מה נבדק ואיך, ומה ממתין לבעלים.
