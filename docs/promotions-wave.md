# גל "מבצעים" — מבצעים מה-CRM, מחיר מבצע ותווית הנחה באתר

נכתב 2026-09-27. זה ה-FLOW המלא: מה בעל העסק עושה, מה קורה באתר, איך זה בנוי, ובאיזה סדר זה נבנה.

## הבקשה

"אני רוצה שתהיה אופציה לעשות מבצעים דרך ה-CRM, ושהפריטים יופיעו תקין עם הנחה באתר, ועם סמל של כמות ההנחה."

## ה-FLOW של בעל העסק (מה עושים ב-CRM)

1. **ניהול → מבצעים → "מבצע חדש".**
2. **שם המבצע** (פנימי, למשל "חנוכה 2026"), ו**תווית לאתר** (לא חובה, למשל "מבצע חנוכה").
3. **אחוז הנחה** — 1 עד 70. ההנחה נוספת על המחיר שהאתר גובה היום.
4. **על מה המבצע חל** — אחת משלוש:
   - כל החנות;
   - קטגוריות — כולל כל תתי-הקטגוריות שלהן;
   - מוצרים מסוימים — חיפוש ובחירה.
5. **תאריכים** — התחלה (עכשיו או מועד עתידי) וסיום. **תאריך סיום הוא חובה**: מבצע בלי סוף הוא מחיר חדש, לא מבצע.
6. **תצוגה מקדימה** לפני שמירה: כמה מוצרים נכללים, מחיר לפני ואחרי לדוגמה, המחיר הנמוך והגבוה אחרי ההנחה. הנחה מעל 50% מבקשת אישור נוסף.
7. **שמירה.** תוך דקה בערך האתר מתעדכן — ראו הסעיף הבא.
8. **בזמן המבצע** — ברשימת המבצעים רואים מה פעיל, מה מתוכנן ומה הסתיים, ויש כפתור **"סיים עכשיו"**.
9. **בסוף** — המבצע נגמר לבד בתאריך הסיום, והמחירים חוזרים לרגילים. כל הזמנה שנעשתה במבצע מסומנת בו, לדוח.

## מה הלקוח רואה באתר

| מקום                                      | בלי מבצע (היום) | במבצע                                                                                            |
| ----------------------------------------- | --------------- | ------------------------------------------------------------------------------------------------ |
| כרטיס מוצר (קטגוריה, חנות, חיפוש, המלצות) | מחיר אחד        | מחיר המבצע, המחיר הרגיל מחוק, ותווית **‎-20%** בפינת התמונה                                      |
| עמוד מוצר                                 | מחיר אחד        | מחיר מבצע, מחיר רגיל מחוק, תווית ההנחה, שם המבצע ו"המבצע בתוקף עד DD.MM"                         |
| עגלה, עגלה צפה, קופה                      | מחיר השורה      | מחיר המבצע בשורה, ו"חסכתם ₪X במבצע" בסיכום                                                       |
| החיוב בפועל (שרת)                         | מחיר רגיל       | מחיר המבצע — השרת מחשב בעצמו מול המבצע הפעיל ברגע ההזמנה                                         |
| Google (JSON-LD ופיד Merchant)            | price           | price = מחיר המבצע, priceValidUntil = סוף המבצע; בפיד `sale_price` ו-`sale_price_effective_date` |

## כללי יושר (חוק הגנת הצרכן §2)

- **ה"לפני" אמיתי:** המחיר המחוק הוא המחיר שהאתר גובה היום על אותו מוצר, לא מחיר מומצא ולא "מחיר מחירון".
- **האחוז אמיתי:** התווית מחושבת מהמחירים המעוגלים שמוצגים, כך ש-‎-20% תמיד תואם את שני המספרים שליד.
- **יש תאריך סיום, והוא מוצג.**
- **מבצעים לא נערמים:** אם מוצר נכלל בשני מבצעים, חל הגבוה מביניהם. הנחת מועדון (5%) ממשיכה לחול על סכום העגלה, כמו היום.
- **השרת לא גובה יותר ממה שהוצג:** אם מבצע הסתיים בזמן שהלקוח בקופה, ההזמנה נעצרת עם הודעה שהמחירים עודכנו, במקום לחייב סכום גבוה מזה שראה.

## איך זה בנוי (FLOW טכני)

```
CRM (/admin/promotions)
   │  createPromotion / updatePromotion / endPromotion   (server fns, admin only)
   ▼
public.promotions  ── name, badge_label, percent_off, scope, category_ids[], product_ids[],
   │                  starts_at, ends_at, is_active
   ▼
active_promotion_index()   SQL, SECURITY DEFINER, grant anon
   │   מבצעים פעילים עכשיו → שורה לכל מוצר (קטגוריות מורחבות לתתי-קטגוריות),
   │   ושורת "כל החנות" (product_id null); המבצע הגבוה לכל מוצר
   ├──────────────► root loader (SSR) → usePromoIndex() → ProductCard / PDP / עגלה / קופה / חיפוש
   ├──────────────► placeOrder (שרת): unit_price = promoPrice(effectivePrice(base))
   │                 order_items.promotion_id ← המבצע שחל
   └──────────────► /feed.xml: g:sale_price + g:sale_price_effective_date
```

כל החישוב במקום אחד: `src/lib/promotions.ts` — `promoFor(index, productId)` ו-`promoPrice(regular, promo)`. אותה פונקציה רצה בדפדפן ובשרת, כמו `pricing.ts` היום.

### שלב א — הליבה (אין שינוי נראה עד שנוצר מבצע) — הושלם, #145

- טעינה ב-root loader, והוק `usePromoIndex()` שמתרענן כל דקה.
- תצוגה: כרטיס מוצר, עמוד מוצר ו-JSON-LD, עגלה צפה, עמוד עגלה, קופה, חיפוש בכותרת, המלצות בעגלה.
- שרת: `placeOrder` מחיל את המבצע, שומר `promotion_id`, ועוצר אם הסכום גבוה ממה שהלקוח ראה.
- פיד Merchant.
